> چه چیزی محکم است، کجا هنوز جای کار دارد، و هر مورد **با کد به‌سادگی حل می‌شود**،

## ۱) نقشهٔ کلی سیستم

```
ZIP خام ──parser──▶ SQLite هر خودرو ──┐
                                       ├─ Django API ──▶ Next.js UI ──▶ کاربر
        ساخت آفلاین (bge-m3)           │   ├─ مرور دفترچه (car_view)
   index.rag.db (dedup, int8+FTS+graph)│   ├─ /api/assist  (RAG ترکیبی)
   diag/<car>.diag.db (DTC/symptom)    │   ├─ /api/diagnose (موتور قاعده‌محور)
   feedback.db (HITL: کلیک/رأی/pin)    │   ├─ /api/feedback/* (HITL)
   eval/ (گزارش‌های ارزیابی آفلاین)    │   └─ /api/eval/report
                                       └─ /api/chat (Next) ─▶ Metis (فقط جمله‌بند)
```

**حالِ هر لایه (حسِ نسبی، نه عدد دقیق):**

| لایه | وضعیت | یادداشت |
|------|-------|---------|
| خط لولهٔ داده (parser → SQLite) | ۹۰٪ پایدار | اصل‌ها read-only + checksum؛ تکرارپذیر |
| ایندکس RAG (dedup, int8, FTS, graph) | ۹۰٪ | طراحی تمیز؛ یک‌بار ساخت، سرو سبک |
| بازیابی RAG (`retrieve.py`) | ۸۵٪ | حالا fusion وزن‌دار + کالیبراسیون + کف grounding |
| موتور تشخیص (`diag.py`) | ۷۰٪ | قوی ولی **لایه‌های پیشرفته به آن منتقل نشده** (بخش ۴-A) |
| سرو/کارایی (`service.py`, `store.py`) | ۷۰٪ | کش درون‌پردازه‌ای؛ اتصال DB هر درخواست تازه باز می‌شود |
| HITL (بازخورد بسته) | ۸۰٪ | پیاده شد؛ ولی endpoint کارشناس بدون auth |
| ارزیابی آفلاین | ۷۵٪ هارنس آماده | gold set واقعی هنوز نیست (نیاز داده) |
| شفافیت/تفسیرپذیری | ۸۵٪ | پنل شواهد فقط برای مسیر assist غنی است |
| فرانت‌اند مرور | ۸۵٪ | سرچ‌بار اصلی هنوز LIKE است نه RAG (بخش ۴-B) |
| آمادگی production | ۳۰٪ | DEBUG/SECRET/CORS/ALLOWED_HOSTS و API_BASE هنوز dev |
| امنیت | ۴۰٪ | بدون auth/rate-limit روی endpointهای حساس |

## ۲) نقاط قوت (نگه‌داشتنی)

- **حذف‌تکرار content-addressed**: ۲۶۳k صفحه → ~۷۳k blob یکتا؛ ۴× وکتور کمتر.
- **بازیابی ترکیبی هوشمند**: dense+sparse با **RRF وزن‌دارِ تطبیقی** (کد→کلیدواژه،
  جملهٔ فارسی→معنایی) + امتیاز کالیبره (`scoring.calibrate`) + **کف grounding**
  (پرسش بی‌ربط رد می‌شود، نه پاسخ گمراه‌کننده).
- **موتور تشخیص deterministic** با confidence سه‌سطحیِ صادقانه (لینک جدول کارخانه >
  تطبیق معنایی مطمئن > هم‌زیرسیستمی).
- **شفافیت high-stakes**: پنل شواهد، نوار اطمینان، badge grounded/mode، «چرا این پاسخ؟».
- **حلقهٔ بستهٔ HITL** + **هارنس ارزیابی آفلاین صفر-LLM** (Hit@k/MRR/nDCG/refusal/calibration).
- **برگشت‌پذیری کامل**: همه‌چیز زیر `_rag/`؛ اصل‌ها هرگز نوشته نمی‌شوند.

## ۳) چه چیزی **با کد حل نمی‌شود** (نیاز انسان/داده/زیرساخت)

| مورد | چرا کدنویسی کافی نیست |
|------|------------------------|
| کیفیت gold set ارزیابی | به پرسش‌های واقعیِ برچسب‌خورده یا کارشناس دامنه نیاز دارد؛ هارنس آماده است ولی داده نه. خودبه‌خود از کلیک‌های واقعی رشد می‌کند. |
| میزبانی production (TLS, CDN, secret manager) | تصمیم زیرساختی/عملیاتی است، نه فقط کد. |
| کش مشترک بین چند worker (gunicorn) | نیاز به Redis/Memcached دارد؛ انتخاب زیرساخت. |
| سقف دقت مدل امبدینگ | فقط `bge-m3` آفلاین است؛ reranker بهتر = دانلود+RAM بیشتر (کاربر رد کرد). سقف، مدل‌محور است. |
| ادغام معناییِ پارافریز فارسی | «روغن ترمز» vs «روغن موتور» شباهت ≈۰٫۸۱ — پایین‌آوردن آستانه ناامن است؛ نیاز به سیگنال/دادهٔ بهتر، نه کد ساده. |
| وابستگی به Metis (streaming/سلامت سرویس) | به توان API خارجی بستگی دارد. |

## ۴) کارهای باقی‌مانده (دقیق، با مرجع کد)

دسته‌ها: 🟢 با کد آسان · 🟡 با کد متوسط · 🔴 با کد سخت · ⚪ غیرکدی.

### A) مسیر تشخیص هنوز ارتقا نیافته (کیفیت) — 🟡
موتور `diag.py` از بهبودهای RAG بهره نمی‌برد:
- `_diagnose_by_symptom` هنوز **RRF بی‌وزن** دارد (`diag.py:245-249` تابع `bump`) —
  بدون `classify_query`/`calibrate`/feedback/کف grounding.
- بدون **کش معنایی** روی diagnose (`service.diagnose` فقط کش کلید-دقیق دارد).
- بدون **کف grounding** روی علامت → کاندیدای ضعیف با `confidence=0.35` می‌تواند گمراه کند.
- diag فیلدهای `explain`/`matched_via`/`confidence_band` را برای پنل شواهد تولید نمی‌کند
  (پنل فقط منابع مسیر assist را غنی نشان می‌دهد؛ منابع diagnose فاقد نوار اطمینان‌اند).
- **راه‌حل:** پورت Layer B/C/E به `diag.py`؛ استفادهٔ مشترک از `scoring.py`.

### B) سرچ‌بار اصلی از RAG استفاده نمی‌کند — 🟡 (ارزش بالا)
`SearchBox.jsx` + صفحهٔ `/search` به `car_view ?q=` می‌زنند که **`LIKE '%q%'`**
زیررشته‌ایِ ASCII، فقط-انگلیسی و per-car است (`views.py:255-263`). جست‌وجوی معنایی
فقط در دستیار هست. placeholder هم انگلیسیِ `dir=ltr` است (`SearchBox.jsx:97`).
- **راه‌حل:** سرچ را به `/api/assist` (یا یک `/api/search` سبک روی همان retriever)
  وصل کن تا فارسی/معنایی شود؛ placeholder دوزبانه.

### C) کارایی/پایداری سرو — 🟢/🟡
- `store.open_index()` در **هر درخواست** اتصال تازه می‌سازد و **افزونهٔ sqlite-vec
  را دوباره بار می‌کند** (`store.py:26-39`؛ هم در retrieve هم diag). یک اتصال
  read-only گرم (thread-local) اضافه کن. 🟢
- `feedback.pinned_match` در هر assist یک اتصال باز می‌کند (`feedback.py`) حتی وقتی
  جدول overrides خالی است — کش کن یا وقتی خالی است رد شو. 🟢
- مدل امبدینگ تنبل بار می‌شود (اولین پرسش ~۱۰-۱۵s سرد). یک **warmup** هنگام
  استارت سرور (thread پس‌زمینه) اضافه کن. 🟢
- کش‌ها درون‌پردازه‌ای‌اند → بین چند worker مشترک نیستند (برای runserver تک‌پردازه
  اوکی؛ برای مقیاس نیاز Redis — ⚪/🔴).

### D) آمادگی production — 🟢 (کد) + ⚪ (عملیات)
- `settings.py`: `DEBUG=True` (خط ۲۶)، `SECRET_KEY` هاردکدِ `django-insecure-`
  (خط ۲۳)، `ALLOWED_HOSTS=[]` (خط ۲۸)، `CORS_ALLOW_ALL_ORIGINS=True` (خط ۵۴).
  همه را env-driven کن. 🟢
- `kg_frontend/src/utils/api.jsx:2`: `API_BASE` هاردکدِ `http://127.0.0.1:8000` —
  هیچ `NEXT_PUBLIC_API_BASE` ندارد؛ هر deploy غیرلوکال می‌شکند. 🟢
- `/media` فقط در `DEBUG` سرو می‌شود؛ production به nginx/whitenoise نیاز دارد. ⚪
- `run_server.sh` از `runserver` (سرور توسعه) استفاده می‌کند؛ production نیاز
  gunicorn/uvicorn دارد. ⚪

### E) امنیت — 🟡 (مهم)
- `/api/feedback/pin/` (پاسخ «تأییدشدهٔ کارشناس») و `/admin-review` **بدون auth**اند
  (`views.py: feedback_pin_view`). هرکس می‌تواند با pin، رتبه‌بندی را مسموم کند.
  auth (Django auth/توکن) لازم است. 🟡 — اولویت بالا.
- بدون **rate-limit** روی `/api/chat` (Metis پول خرج می‌کند) و `/api/assist` (embed).
  `django-ratelimit` یا middleware. 🟡
- CSRF روی APIها غیرفعال است (`csrf_exempt`) — برای API توکنی قابل‌قبول، ولی با auth
  بازنگری شود.

### F) جمله‌بند (Metis) — 🟡 + ⚪
- تک‌وابستگی خارجی؛ اگر Metis down شود دستیار می‌افتد. یک **fallback بدون‌LLM**
  (برگرداندن منابع ساختاریافته بدون جمله‌بندی) اضافه کن. 🟡
- بدون **streaming**؛ کاربر تا پایان کل پاسخ منتظر می‌ماند. SSE. 🔴 (وابسته به توان Metis)
- **faithfulness** زمان اجرا تضمین نمی‌شود (فقط با پرامپت). اعتبارسنجی کن که
  hrefهای `[BUTTON]` ⊆ منابع بازیابی‌شده باشند و لینک‌های توهمی حذف شوند. 🟢
- ابعاد LLM-judge ارزیابی (faithfulness/relevance) عمداً کنار گذاشته شد (تصمیم کاربر:
  صفر-LLM)؛ می‌توان به‌صورت آفلاین/اختیاری افزود. 🟡

### G) بلوغ ارزیابی/تست — 🟢 + ⚪
- gold set فعلاً یک seed تک‌ردیفی است؛ به پرسش‌های واقعیِ برچسب‌خورده نیاز دارد
  (از کلیک رشد می‌کند). ⚪ (داده)
- بدون **CI**؛ تست/ارزیابی خودکار اجرا نمی‌شود (GitHub Actions). 🟢
- بدون **تست یکپارچهٔ committed** برای خط لولهٔ retrieve/service/feedback (فقط
  `scoring`/`evalmetrics` یونیت‌تست‌اند). یک `Django TestCase` با ایندکس کوچک fixture. 🟢

### H) صحت کش هنگام تغییر — 🟢
- بعد از یک pin/رأی جدید، `blob_boost_map` باطل می‌شود ولی **کش پاسخ (`_CACHE`) و
  کش معنایی (`_SEM_CACHE`) باطل نمی‌شوند** → پاسخ کش‌شده تا انقضای TTL، pin تازه را
  منعکس نمی‌کند. در `rate`/`pin` کش‌ها را پاک کن. 🟢

### I) پولیش UX فرانت‌اند — 🟢/🟡
- بدون typing/streaming (بالا).
- پنل شواهد برای diagnose تُنُک است (بخش A).
- سرچ‌بار انگلیسی‌-only (بخش B).
- `/admin-review` فقط خواندنی است؛ دکمهٔ واقعی **pin** ندارد (باید `/api/feedback/pin/`
  را curl کرد). یک فرم pin اضافه کن. 🟢

### J) چرخهٔ عمر داده/ایندکس — ⚪
- افزودن خودرو: `build_rag --add` سپس `build_diag`. مستند است. مدل امبد باید یکی باشد.
- reindex خودکار روی دادهٔ جدید نیست (عملیات).

## ۶) ترتیب پیشنهادی اجرا (sprintها)

1. **امنیت پایه + production-config (🟢🟡):** auth روی pin/admin، rate-limit، env کردن
   settings/SECRET/DEBUG/ALLOWED_HOSTS/CORS و `NEXT_PUBLIC_API_BASE`. *(بیشترین ریسک فعلی.)*
2. **یکپارچگی کیفیت (🟡):** پورت fusion وزن‌دار + کالیبراسیون + کف grounding به `diag.py`؛
   غنی‌سازی منابع diagnose برای پنل شواهد.
3. **سرچ معنایی (🟡):** اتصال سرچ‌بار به retriever؛ placeholder دوزبانه.
4. **استحکام سرو (🟢):** اتصال DB گرم + warmup + باطل‌سازی کش روی pin/rate.
5. **اعتماد به پاسخ (🟢/🟡):** اعتبارسنجی لینک‌های [BUTTON]؛ fallback بدون‌LLM؛ شروع streaming.
6. **بلوغ تست/ارزیابی (🟢/⚪):** CI، تست یکپارچهٔ retrieval، رشد gold set از کلیک‌های واقعی.

> نکته: لایه‌های پیشرفتهٔ فعلی (fusion/scoring/HITL/eval/transparency) در
> [assistant.md](assistant.md) بخش «نسخهٔ ۲» مستند شده‌اند؛ ثابت‌های کالیبراسیون
> (`GROUND_SIM_FLOOR=0.55`, `SEM_CACHE_SIM=0.95`) عمدی و اندازه‌گیری‌شده‌اند.
