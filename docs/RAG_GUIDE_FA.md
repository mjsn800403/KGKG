# راهنمای ساخت و اجرای سیستم RAG (دستیار تعمیرات)

این سیستم «مغزِ» دستیار را از **دیتابیس خودروهای خودت** می‌سازد. متیس فقط جمله‌بندیِ فارسی را انجام می‌دهد؛ تمام دانش از همین ایندکس محلی می‌آید.

> ✅ **بدون نیاز به اینترنت.** مدلِ امبدینگ (bge-m3) از قبل روی مک تو هست. هیچ دانلودی لازم نیست.
> ✅ **به دیتابیس اصلی دست نمی‌زند.** فایل‌های خودرو فقط *خوانده* می‌شوند و قبل/بعد چک‌سام می‌شوند تا ثابت شود دست‌نخورده‌اند.
> ✅ **قابل‌ادامه (resumable).** اگر وسط کار قطع شد، فقط دوباره همان فایل را اجرا کن؛ از همان‌جا ادامه می‌دهد.

---

## مرحله ۱ — ساخت ایندکس (یک‌بار، حدود ۱.۵ تا ۲.۵ ساعت)

در ترمینال این دو خط را بزن:
```bash
cd "/Users/mohammadjavadsalimi/Downloads/kg/khadamatsikim/khadamat"
./run_rag_build.sh
```

### در حین اجرا چه می‌بینی؟
خطوطی مثل این، زنده روی صفحه (و هم‌زمان داخل یک فایل لاگ ذخیره می‌شوند):
```
=== safety: checksumming original car DBs ===
=== stage 1: scan + dedup + chunk ===
  leaves=262906  unique blobs=...  (dedup ~72%)
=== stage 2: embed (int8 serve + float ...) ===
    loading embedding model (first load ~20-30s, then embedding starts)...
    model ready; embedding now (progress prints every few seconds) ...
    embedded 1280/46000  (9.2/s, ~81 min left)
    embedded 2560/46000  (9.4/s, ~77 min left)
  ...
=== stage 3: relationship graph ===
  edges: semantic=...  labor_time=...  crosslink=...
=== safety: re-checksumming originals ===
  all 9 original DBs byte-identical (untouched).

RAG build complete in ... s.
```
عدد `embedded X/Y` هرچند ثانیه بالا می‌رود — از روی همان می‌توانی تخمین بزنی چقدر مانده.

### مهم
- **می‌توانی کارهای دیگرت را بکنی**، ولی بهتر است مک خاموش/Sleep نشود تا کار سریع‌تر تمام شود.
- اگر بستی یا قطع شد: **دوباره همان `./run_rag_build.sh` را اجرا کن** — از جایی که مانده ادامه می‌دهد (دوباره از صفر شروع نمی‌کند).
- وقتی دیدی نوشت **`RAG build complete`**، تمام است.

### خروجی را برای من بفرست
آخرِ کار، مسیرِ فایل لاگ چاپ می‌شود (چیزی شبیه):
```
Database_warehouse/_rag/build_YYYYMMDD_HHMMSS.log
```
👉 **همان فایل لاگ را برایم بفرست** (یا کل متنِ پایانِ ترمینال را کپی کن).

## مرحله ۴ — افزودن مدل/دیتابیسِ جدید (برای رشد تا صدها مدل)
وقتی دیتابیسِ خودروی جدیدی به `Database_warehouse/` اضافه کردی، **لازم نیست از اول بسازی.** فقط این را بزن:
```bash
cd "/Users/mohammadjavadsalimi/Downloads/kg/khadamatsikim/khadamat/KG_backend"
RAG_EMBED_MODEL=bge-m3 HF_HUB_OFFLINE=1 .venv/bin/python manage.py build_rag --add
```
- خودش دیتابیس‌هایی که هنوز در ایندکس نیستند را پیدا می‌کند.
- فقط **صفحاتِ واقعاً جدید** را embed می‌کند؛ هر صفحه‌ای که محتوایش قبلاً (در مدلی دیگر) دیده شده، رایگان و فوری به آن وصل می‌شود. برای همین افزودن مدل دهم/صدم معمولاً خیلی سریع است.
- گراف ارتباطی هم فقط برای صفحات جدید به‌روزرسانی می‌شود (نه ساختِ دوباره‌ی کل گراف).
- برای فعال‌شدن موتور تشخیص روی همین خودروی جدید، یک‌بار هم بزن:
  ```bash
  ./run_diag_build.sh --car "<نام دیتابیس خودرو>"
  ```

## چرا سایت کند نمی‌شود؟
- صفحاتِ عادیِ سایت (مرور خودروها) **اصلاً** به این سیستم کاری ندارند؛ فقط «دستیار» از آن استفاده می‌کند.
- جواب‌های پرتکرار **کش** می‌شوند و فوری برمی‌گردند (بدون درگیر کردن مدل).
- پرسش‌های فارسی خودکار با معادل‌های فنیِ انگلیسی غنی می‌شوند (مثلاً «روغن ترمز» → «brake fluid») تا دقت بالا برود.
- روی سرور می‌توانی با `RAG_RERANK=1` یک رتبه‌بندِ دقیق‌تر (cross-encoder) را هم روشن کنی — دقت بیشتر، به قیمتِ کمی منابع بیشتر.

## سؤالات احتمالی
- **خیلی طول می‌کشد؟** حدود ۱.۵ تا ۲.۵ ساعت برای همه‌ی ۹ خودرو. دو دلیلِ سبک بودن: (۱) محتوای تکراری حذف می‌شود (~۷۲٪ برگ‌ها تکراری‌اند)، (۲) مدل با حالت fp16 اجرا می‌شود که ~۳ برابر سریع‌تر و نصفِ رم است.
- **اینترنت لازم است؟** نه، هیچ. مدل از قبل روی مک تو هست.
- **رم زیاد می‌گیرد؟** با fp16 حدود ۱.۲ گیگ (نه ۲.۳). با این حال بهتر است برنامه‌های سنگینِ دیگر را موقع ساخت ببندی تا روان و پایدار بماند.
- **اگر دیدی مدتی روی خط «embedded …» مکث کرد:** طبیعی است — هر چند ثانیه یک خط تازه با تخمینِ زمانِ باقی‌مانده چاپ می‌شود. تا وقتی عددِ `embedded X/Y` بالا می‌رود، در حال کار است.
