# Draft privacy notice for the support chat: structure and proposed wording

**Status:** DRAFT for the owner's and legal review. This is not an approved policy and is not legal advice. Items in [brackets] must be supplied or confirmed by the owner. Nothing here is published.

## 1. Page structure (proposed `/privacy`, public, static)

1. Who we are and how to contact us about privacy
2. What we collect when you use the support chat
3. Why we use it
4. Who can see it
5. Messages we may send you (SMS and email)
6. What stays in your browser, and how to remove it
7. How long we keep it
8. Your choices and requests
9. Service providers
10. Security
11. Changes and effective date

The page is linked from: the chat panel menu, the contact card, the landing footer. A two-line summary appears under the contact card inside the widget.

## 3. Proposed Persian wording for the page (to be reviewed)

### ۱. ما چه کسی هستیم
[نام قانونی شرکت]، [نشانی]. برای پرسش دربارهٔ حریم خصوصی: [ایمیل یا تلفن].

### ۲. چه اطلاعاتی گردآوری می‌شود
وقتی از گفتگوی پشتیبانی استفاده می‌کنید:
* متن پیام‌هایی که می‌فرستید و پاسخ‌هایی که دریافت می‌کنید؛
* نام، شمارهٔ موبایل یا ایمیل، فقط اگر خودتان وارد کنید؛
* صفحه‌ای از سایت که گفتگو را از آن شروع کردید (بدون پارامترهای نشانی) و سایتی که شما را به ما رساند (بدون پارامترها)؛
* زمان پیام‌ها و وضعیت گفتگو (باز، بسته، امتیاز شما)؛
* یک رمزنگاری یک‌طرفهٔ ساده از مشخصات مرورگر شما (نه مشخصات خام) برای تشخیص سوءاستفاده؛ این مقدار برای هر مرورگر مشابه یکسان است و نباید آن را ناشناس‌کننده دانست؛ [مالک: یا نمک‌دار شود یا حذف]؛
* سوابق رویدادهای گفتگو (مثلاً باز شدن، تخصیص، بسته شدن، امتیاز) با شناسهٔ گفتگو و زمان، بدون متن پیام و اطلاعات تماس. این سوابق «ناشناس» نیستند، چون با شناسهٔ گفتگو و زمان ممکن است به یک گفتگو برگردند؛
* در سوابق گفتگو نشانی IP شما ذخیره نمی‌شود، اما نشانی IP هنگام انتقال درخواست از زیرساخت و سرویس‌های امنیتی (مانند Cloudflare و سرور وب) و برای محدودسازی تعداد درخواست‌ها پردازش می‌شود و ممکن است در سوابق آنها بماند [مدت: مالک تأیید کند].

### ۳. چرا استفاده می‌کنیم
برای پاسخ دادن به پرسش شما و پیگیری آن، برای امنیت و جلوگیری از سوءاستفاده، برای مدیریت عملیات پشتیبانی (تخصیص و پیگیری گفتگوها) و برای سنجش کیفیت خدمات به‌صورت آماری. پاسخ‌ها را همیشه کارکنان انسانی می‌نویسند؛ از هوش مصنوعی برای پاسخ دادن به شما استفاده نمی‌شود.

### ۴. چه کسی می‌بیند
فقط کارکنان مجاز پشتیبانی بر اساس نقش‌شان. [پس از تأیید نقش‌ها: اطلاعات تماس شما برای نقش‌هایی که به آن نیاز ندارند پنهان است و هر بار مشاهده ثبت می‌شود.] یادداشت‌های داخلی را شما نمی‌بینید. گزارش‌های آماری مدیریتی فاقد متن پیام و اطلاعات تماس است.

### ۵. پیام‌هایی که برای شما می‌فرستیم
اگر شمارهٔ موبایل یا ایمیل داده باشید، ممکن است هنگام آماده شدن پاسخ یک اعلان کوتاه بدون متن پاسخ بفرستیم. [در صورت فعال شدن پیامک/ایمیل، نام ارائه‌دهنده را اینجا بنویسید.]

### ۶. چه چیزی در مرورگر شما می‌ماند
یک شناسهٔ گفتگو و یک کلید دسترسی در حافظهٔ مرورگر ذخیره می‌شود تا بتوانید گفتگو را بعداً ادامه دهید، و پیام‌های هنوز ارسال‌نشده تا ۲۴ ساعت. با گزینهٔ «حذف این گفتگو از این مرورگر» همه از مرورگر شما پاک می‌شود. روی رایانهٔ مشترک بعد از استفاده این گزینه را بزنید.

### ۷. مدت نگهداری
[مدت نگهداری گفتگوهای بدون اطلاعات تماس]، [مدت نگهداری گفتگوهایی که اطلاعات تماس دارند]، [مدت نگهداری سوابق رویداد]. هنوز هیچ مدتی تصویب نشده است. پس از پایان مرحلهٔ تفصیلی، سوابق رویداد در صورت تصویب به آمار تجمیعی بدون شناسه تبدیل می‌شود. حذف داده‌ها از نسخه‌های پشتیبان بلافاصله انجام نمی‌شود و پس از انقضای نسخه‌های پشتیبان [مدت: مالک] کامل می‌شود.

### ۸. حق‌ها و درخواست‌ها
می‌توانید درخواست دسترسی، اصلاح یا حذف اطلاعات خود را از [مسیر تماس] بدهید. [زمان پاسخ و روش احراز هویت را مالک تعیین کند.]

### ۹. ارائه‌دهندگان خدمات
برای ارسال پیامک: [ارائه‌دهنده]؛ برای ایمیل: [ارائه‌دهنده]؛ برای تأیید امنیتی (جلوگیری از ربات‌ها): Cloudflare Turnstile. [فهرست را مالک نهایی کند.]

### ۱۰. امنیت
دسترسی کارکنان بر اساس نقش و با ثبت رویداد است؛ متن پیام‌ها در سوابق ممیزی ذخیره نمی‌شود. هیچ سامانه‌ای کاملاً بدون خطر نیست؛ [در صورت نیاز: روش اطلاع‌رسانی رخداد امنیتی].

### ۱۱. تغییرات

## 4. Facts the wording relies on (so the page stays true)

| Statement | Backed by | Status |
|---|---|---|
| IP not stored in chat records | no IP column on `SupportThread`; audit skips chat bodies and visitor IP | verified in Phase 2 code and tests |
| The IP address still passes through infrastructure (Cloudflare, nginx logs, the short-lived rate-limit store) | normal request handling | **verified by design**; the page must say only that IP is not kept in conversation records, never that it is not processed |
| Query strings and fragments stripped from page and referrer | `limits.clean_page`, `clean_referrer` | verified by tests |
| Device hash is not reversible | `ua_hash` is an unsalted SHA-256 of the user agent | **claim removed (revision 3)**: low entropy, identical for identical browsers; the draft now says it is not anonymising. Salting or dropping it is an owner decision and a code change outside M0/M1 |
| Events are anonymous | `SupportThreadEvent` carries a thread ref, actor id and time | **claim removed**: described as pseudonymous operational records; no table exists yet (blocked on migration A) |
| Data used only to answer the chat | security, operations and quality measurement are also legitimate uses | **claim removed**: purposes listed honestly |
| Browser token and unsent queue | thread id and token in `localStorage`, unsent queue in `sessionStorage` (24 h cap) | implemented in M1 widget storage module; section 6 wording matches |
| Replies are written by humans | architecture constraint | by design |
| Browser keeps thread id, token, unsent queue up to 24 h | spec 12.1 | proposed behaviour, not built |
| Contact hidden for many roles | role model | proposed, not built |
| No SMS or email is sent today | notification modes `off` | verified |
| Retention periods | none approved | **owner to supply** |
